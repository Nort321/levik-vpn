# Архитектура Android-клиента Levik VPN

## Границы репозитория

Данный репозиторий содержит один основной компонент продукта: нативный клиент Android в каталоге `levik_vpn_android/`. Корневые файлы обеспечивают управление проектом, документацию релизов и CI-пайплайны.

Серверная часть, веб-сайт, Mobile BFF, Telegram-бот, база данных и инфраструктура развертывания являются внешними сервисами и не входят в состав репозитория. Модели API и пути эндпоинтов в коде Android описывают клиентский контракт взаимодействия.

## Архитектурные слои Android-приложения

Приложение разделено на независимые слои:

- **Пользовательский интерфейс (UI Layer)**: Jetpack Compose, Material 3, ViewModel и реактивное состояние (Kotlin StateFlow).
- **Сетевой слой (Network Layer)**: OkHttp, kotlinx.serialization, типизированные контракты Mobile API с валидацией схем ответов.
- **Аппаратная криптография (Security / Keystore Layer)**: генерация ключевых пар в Android Keystore (StrongBox / TEE) для идентификации устройства и подписи запросов (`X-Device-Signature`).
- **Локальное хранилище (Data / Storage Layer)**: EncryptedSharedPreferences и зашифрованная БД Room (AES-256-GCM) для безопасного хранения токенов и профилей.
- **VPN-сервис (VPN Core / Tunnel Layer)**: реализация `android.net.VpnService`, управляющая жизненным циклом сетевого туннеля и нативным процессом `libXray`.
- **Фоновые задачи**: WorkManager для фоновой синхронизации статуса подписки и проверки обновлений.

## Границы доверия и безопасность

- **Клиентское устройство не является доверенным авторитетом**: внешние серверные сервисы самостоятельно применяют проверки аутентификации, подписки и времени жизни сессий.
- **Входящие ответы API валидируются на границе слоев**: защита от поврежденных данных, инъекций и изменения формата.
- **Защита рабочих профилей VPN**: профили шифруются при сохранении, исключаются из логов и очищаются при выходе из аккаунта.
- **Обработка сбоев**: приложение корректно обрабатывает истечение сессий, отзыв устройств, смену сети (Wi-Fi ↔ LTE), перезапуск процесса и восстановление туннеля.

## Нативное ядро libXray

Файл `libXray.aar` является внешней бинарной зависимостью и исключен из Git. Скрипт `scripts/ci/fetch-libxray.sh` загружает официальный релизный архив `v26.7.28`, проверяет его SHA-256 хэш, извлекает AAR и повторно верифицирует его целостность перед сборкой.
